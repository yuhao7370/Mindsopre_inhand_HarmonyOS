# 项目 UI 规范

本文件作用于整个项目。后续新增或重做界面时，除非用户明确指定其他方向，都应遵循以下规则。

## 设计目标

- 使用 HarmonyOS 原生组件与交互习惯，界面轻、清晰、稳定。
- 旧界面只作为功能与信息来源，不沿用 Android 式重阴影、重边框或复杂叠层。
- 优先减少装饰和状态变化；不为单个页面引入第三方 UI 库或一次性抽象。

## 页面结构

- 页面左右安全边距默认 16vp，间距优先使用 8vp 网格。
- 顶级入口页可以使用紧凑品牌头图；普通功能页使用原生标题栏，不强制添加头图。
- 头图与内容不重叠、不通过圆角形变制造层级。
- 需要吸顶时：头图自然上滑离场，随后显示轻量标题栏。禁止滚动过程中改变内容容器圆角、缩放卡片或制造双层滚动错觉。
- 分类标题左对齐，可使用短蓝色强调条；避免居中标题配长分割线。

## 卡片与列表

- 功能中心默认使用双列卡片；长文本、表单和设置项使用单列列表。
- 功能卡片使用白色背景、约 15–16vp 圆角和 1vp 浅蓝灰边框（参考 `#E8EDF5`）。
- 卡片不使用常驻阴影；按压时仅增加轻微底色或透明度反馈。
- 卡片整体可点击，最小触控尺寸 44vp；标题允许两行，不得因截断造成歧义。
- 不同时叠加粗边框、明显阴影、渐变底色和大圆角。

## 图标

- 功能图标采用圆角细线、纯 2D 的统一风格，主色为蓝色，青色仅作少量强调。
- 禁止 3D、透视、玻璃质感、渐变、高光、投影和 emoji 风格。
- 图标使用一致画布、留白和视觉线宽，在 40–48vp 显示尺寸下仍应清楚。
- 每个功能使用独立语义图标；隐藏功能可保留资源，但不得因此显示入口。

## 色彩与文字

- 页面以白色和浅灰背景为主，品牌蓝用于主操作、选中态和少量强调。
- 正文使用系统字体；标题、正文、辅助文字保持清楚的字号和字重层级。
- 文字与背景必须保持可读对比度；状态不能只靠颜色表达。
- 文案优先简短、直接，不添加装饰性口号。

## 底部导航

- 主页面保留现有圆角悬浮导航：左右和底部留出安全距离，白色胶囊背景，轻量阴影。
- 当前页使用浅蓝胶囊选中态；未选中项保持中性文字与线性图标。
- 页面内容必须预留底部空间，最后一个操作项不得被导航栏遮挡。

## 动效与状态

- 动效只用于解释状态变化，默认 150–220ms，使用自然缓动。
- 滚动、返回、加载和按压反馈应使用 HarmonyOS 原生能力。
- 所有异步功能必须提供加载、成功、失败和可重试状态；失败时保留用户已选择的输入。
- 尊重系统安全区、字体缩放和窗口尺寸变化。

## 功能与可见性

- UI 重做不得改变既有路由、推理流程、权限或数据语义。
- `FeatureCatalog.ets` 的 `visibleByDefault` 是体验中心入口可见性的唯一依据。
- 自定义模型及其他当前隐藏功能继续隐藏，除非用户明确要求重新启用；实现和路由可以保留。

## 实施与验证

- 优先复用项目已有主题、间距和原生组件；只有第二个真实页面需要时才抽取共享组件。
- 新资源使用语义化文件名，替换旧资源前保留可回退版本。
- 每次 UI 修改至少检查：初始状态、滚动后状态、长文案、按压反馈、底部安全区和功能跳转。
- 在 DevEco Studio 模拟器验证实际布局；涉及体验中心时同时截图顶部和滚动后状态。
