# 学院教程文案自然化设计

## 目标

使用 `humanizer-zh` 重写学院页本地快速入门和对应实验记录。文字要像开发者亲手做完实验后写下的教程，读起来轻松一些，但仍是可靠的技术内容。

## 改写范围

- `entry/src/main/ets/common/data/CollegeLocalQuickStart.ets` 中五章教程的标题、学习目标、正文、代码块标题和实测说明。
- `docs/tutorials/mindspore-digits-lenet-run.md` 中除代码、命令和数据表以外的中文说明。
- `CollegePage.ets` 中“本地快速入门”区域的标题、副标题和固定标签。

Python 脚本不改。

## 两层语气

### 应用内教程

采用面对学习者的教学口吻：

- 句子比当前版本短，先说要做什么，再解释原因。
- 可以使用“我们”“先”“接着”“这里要注意”等自然表达。
- 不使用卖萌、感叹号、网络流行语或过度鼓励。
- 每段只处理一个重点，手机上扫读时不需要反复回看。
- 技术限制直接说清楚，不使用“本次没有宣称”“明确标注该边界”等报告式措辞。

### Markdown 实验记录

保持开发文档语气：

- 写成一次真实实验的复盘，不写成宣传稿或验收报告。
- 允许使用第一人称复数，但不频繁插入主观感叹。
- 删除重复的真实性声明；数据集区别和端侧限制各集中说明一次，后文只在需要时提醒。
- 保留排错过程，因为真实失败能帮助读者复现。

## 必须原样保留的内容

- Python、MindSpore、PyTorch、torchvision、scikit-learn、NumPy 和 Pillow 的版本。
- digits 不是标准 MNIST 的事实。
- 数据规模、切分数量、张量形状、数据类型和布局。
- 网络结构、参数、训练轮数、学习率、批大小。
- 两次运行的准确率、耗时和波动说明。
- CKPT、MindIR 的大小、预测结果和 logits 差值。
- MindIR、MindSpore Lite `.ms`、NCHW、NHWC 和 `converter_lite` 的接入限制。
- 所有代码、命令、日志、文件名和 API 名称。

可以调整数字周围的中文句式，不能改数字本身。

## 需要去除的写作痕迹

- “本教程不是……而是……”一类否定式排比。
- “为了保持完全离线”“因此本次没有声称”等辩解式表达。
- “完整复现”“真实运行路径”“明确标注边界”等验收报告用语。
- 连续多句采用相同长度和结构。
- 同一限制在多个章节反复解释。
- “后续真正接入至少需要”等模板化展望标题。

## 示例

改写前：

> 本教程不是一段概念介绍，而是已经在本机执行过的训练、评估和导出记录。

改写后：

> 这套流程已经在本机跑过一遍：训练、评估和导出都留下了实际结果。

改写前：

> 所以本次没有声称完成 Lite 转换或 API 24/arm64 端侧验证。

改写后：

> 目前只走到了桌面 MindIR。Lite 转换和 HarmonyOS 端侧运行还没做，别直接把这个文件塞进应用。

## 验证

- LocalUnit 继续验证五章顺序、内容完整、无 URL 和无“参考视频”。
- 对改写后的两份文字执行关键词检查，确认版本、准确率、耗时、形状和文件大小仍然存在。
- 重新构建 HAP。
- 在模拟器查看首章、训练结果章和导出章，确认段落长度适合手机阅读，代码没有溢出。
- 通过 `humanizer-zh` 的直接性、节奏、信任度、真实性和精炼度五项自评，目标不低于 45/50。
