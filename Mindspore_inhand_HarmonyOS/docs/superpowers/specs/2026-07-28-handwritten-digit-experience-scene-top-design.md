# 手写数字识别体验与场景检测置顶设计

## 目标

本次改动包含两个彼此独立、但需要一起完成的界面目标：

1. 在体验区新增“手写数字识别”，支持连续摄像头识别、拍照识别和相册识别。
2. 将场景检测静态页的内容起点调整到与手势识别一致的位置，解决页面整体偏下的问题。

手写数字识别使用学院教程中已经训练并验证过的 LeNet 模型，不在应用内训练，也不返回随机或占位结果。

## 体验入口与路由

- “手写数字识别”放在体验区“视觉图像技术”中，紧跟“图像分类”。
- 体验区只显示一个功能卡片；卡片使用独立的扁平 2D 图标，不复用其他功能图标。
- 内部使用两个原生路由：
  - 静态路由：相册、相机和单次识别。
  - 实时路由：连续读取摄像头画面并刷新识别结果。
- 两个路由都复用 `FeatureRuntimePage`，不新建重复的相机、相册或生命周期页面。
- 静态路由通过现有“实时识别”按钮进入实时路由，交互方式与手势识别一致。

## 页面设计

### 静态识别

静态页沿用手势识别的页面结构和尺寸：

- 原生标题栏位于顶部。
- 第一块内容是 4:3 图片预览。
- 第二块是状态卡。
- 操作区保持双列按钮：
  - 相册
  - 相机
  - 实时识别
  - 开始识别或重试
- 结果卡显示：
  - 预测数字
  - 置信度
  - 其余置信度较高的候选数字，最多三项

失败时保留用户选中的图片，允许直接重试。页面不增加 WebView、第三方 UI 库或单独的绘图输入板。

### 实时识别

- 页面结构沿用手势识别实时页。
- 摄像头画面保持正确比例和方向，支持前后摄切换。
- 识别结果显示当前数字和置信度。
- 复用现有实时循环，禁止同一时间并发运行两次推理。
- 页面退到后台、切换输入或离开路由时停止实时循环并释放摄像头。

### 相机兼容

- 真机使用 HarmonyOS 原生相机选择器拍照。
- API 24 模拟器没有可用相机选择器时，退回应用内相机预览并执行一次当前帧识别。
- 该回退只解决模拟器能力缺失，不改变真机交互。

## 模型与推理契约

模型来源是：

`docs/tutorials/college-hap/college-hap.zip`

其中：

- 源模型：`artifacts/lenet_mnist.mindir`
- 训练数据：标准 MNIST
- 网络：LeNet 风格卷积网络
- 训练后最佳测试准确率：98.87%
- 桌面回载验证：标签 7，预测 7，导出前后 logits 最大绝对差 0.0

开发时使用 MindSpore Lite 官方转换工具将 MindIR 转为 `.ms`，应用只打包并加载 `.ms` 文件。模型资源需要锁定：

- 源 MindIR 的 SHA-256
- `.ms` 文件的字节长度和 SHA-256
- 输入形状、输出形状和数据类型
- HAP 中的资源路径和双 ABI 结构

运行时契约：

- 输入：`float32 [1, 1, 28, 28]`
- 输出：`float32 [1, 10]`
- 输出语义：0 到 9 的 logits
- 最终结果：logits 最大值对应的数字
- 置信度：对 10 个 logits 做稳定 softmax 后得到

模型加载、输入形状、输出形状或输出数值不合法时必须失败，不得生成随机结果。

## 图片预处理

手机照片和摄像头画面通常是黑字白底，而 MNIST 是亮色笔画配深色背景，因此预处理需要统一两类输入。

处理顺序：

1. 按图片元数据和摄像头旋转信息得到正向像素。
2. 转为灰度图。
3. 使用图像边缘像素估计背景亮度。
4. 背景偏亮时自动反色；背景偏暗时保持亮色笔画。
5. 根据背景差异定位数字前景。
6. 找不到足够前景或对比度过低时返回“未检测到清晰数字”。
7. 裁切数字边界，保留少量边距并补成正方形。
8. 将数字主体缩放到不超过 20×20，再放入 28×28 画布。
9. 按像素重心平移，使数字接近 MNIST 的居中方式。
10. 将像素缩放到 0–1，再按 `(x - 0.1307) / 0.3081` 归一化。
11. 按 NCHW 顺序写入 float32 缓冲区。

静态、相机和实时模式必须共用同一套预处理，避免三种输入得到不同语义。

## 服务边界

新增手写数字服务只负责三件事：

1. 把输入图片预处理成模型张量。
2. 调用已有 MindSpore Lite 模型运行器。
3. 校验并解码十分类输出。

体验目录、路由、实时循环、相机、相册和状态 UI 继续使用现有实现。只有已经出现第二个真实使用者的通用逻辑才允许抽取；不为未来功能增加工厂、插件或配置系统。

## 测试图片

使用内置 imagegen 分别生成三张项目测试图片：

- 手写数字 2
- 手写数字 7
- 手写数字 9

图片要求：

- 一张图只出现一个数字。
- 黑色笔迹写在接近白色的纸面上。
- 数字完整，四周留白。
- 允许轻微真实笔触差异，但不包含其他文字、水印、装饰或多个数字。

最终采用的图片保存到项目测试素材目录，不打入生产 HAP。每张图片先通过桌面 MindIR 和应用一致的预处理验证，只有预测正确的图片才进入模拟器验收。

## 场景检测置顶

场景检测静态页保留现有预览、状态卡、按钮和结果卡，只调整滚动内容的对齐方式：

- `Scroll` 内容使用与手势识别相同的 `Alignment.TopStart`。
- 顶部页边距、4:3 预览尺寸和卡片间距与手势识别一致。
- 不修改场景检测模型、标签、相机方向、推理频率或结果排序。

模拟器截图中，场景检测和手势识别的第一张预览卡顶部坐标应在同一间距节奏内。

## 错误处理

- 模型资源缺失或校验失败：显示模型不可用并允许重试。
- 图片解码失败：保留当前输入并显示读取失败。
- 数字不清晰或没有可用前景：显示未检测到清晰数字。
- 推理失败、输出为空、形状错误或含非有限值：显示识别失败，不显示旧结果。
- 相机或媒体权限被拒绝：保留页面并提供重试入口。
- 实时单帧失败：保留相机预览，下一轮可继续推理；连续失败时显示可见状态。

## 验证

### 自动检查

- 体验目录、路由、工作流、图标和多语言资源测试。
- 黑字白底、白字黑底、低对比度、偏心数字和空白图的预处理测试。
- 稳定 softmax、十分类解码、非有限值和错误输出形状测试。
- `.ms` 模型长度、SHA-256、输入输出契约和 HAP 资源检查。
- LocalUnit、i18n、共享 UI、主 HAP 和 ohosTest HAP 构建。
- 主 HAP 与 ohosTest HAP 同时包含 `arm64-v8a,x86_64`。

### 模拟器验收

只使用 HDC 原生触点、布局树和截图：

1. 体验区能看到“手写数字识别”，并位于图像分类之后。
2. 静态页与手势识别页面结构一致。
3. 三张生成图片通过相册识别，预测与桌面验证一致。
4. 相机按钮在模拟器上进入内联回退并能执行单帧识别。
5. 实时模式能打开摄像头、持续输出非空结果并正确停止。
6. 前后摄切换后预览方向和比例正常。
7. 场景检测首张预览卡与手势识别一样置顶。

## 非目标

- 不在应用中训练或微调 MNIST。
- 不增加手写画板。
- 不替换现有图像分类、自定义模型或手势识别功能。
- 不声称生成的三张图片代表完整准确率。
- 不为相机选择器增加非原生替代页面。
