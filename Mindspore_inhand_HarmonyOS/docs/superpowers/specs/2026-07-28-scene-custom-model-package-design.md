# 场景检测入口与自定义模型包设计

## 目标

1. 在体验中心高级区重新显示“场景检测”。
2. 重新显示“自定义模型”，并让用户选择一个模型包后，由应用先判断输入是图片还是文字，再执行真实的 MindSpore Lite 端侧推理。
3. 不再把缺少语义的前十个浮点数当成最终结果。模型输出按清单解码为分类标签、文字或原始张量。

本功能只支持单次前向推理。聊天模型等逐 token 自回归生成不在本次范围内。

## 已确认的根因

- 场景检测服务、模型和路由都存在，入口仅因 `FeatureCatalog.ets` 中 `visibleByDefault: false` 被隐藏。
- 自定义模型当前确实调用 MindSpore Lite，不包含随机数推理。
- 当前实现把所有模型固定为单个 `float32 NHWC [1,224,224,3]` 图片输入，并只显示前十个原始浮点数。其他图片契约和所有文字模型都会被拒绝或产生难以理解的结果。
- 自然语言不能只靠 `.ms` 张量形状可靠分词。文字模型必须随包提供 tokenizer 和输入输出契约。

## 入口

`FeatureCatalog.ets` 中以下项目设为默认可见：

- `scene`
- `custom`

两者继续位于高级区“视觉图像技术”，复用现有路由和图标，不新建入口页。

## 模型包

用户选择一个 ZIP：

```text
model-package.zip
├─ manifest.json
├─ model.ms
├─ labels.txt
└─ tokenizer.ttok
```

只有 `manifest.json` 和 `model.ms` 必需。`labels.txt` 仅用于分类输出，`tokenizer.ttok` 仅用于文字输入或文字输出。

模型包只允许根目录文件。清单中的文件名不得包含 `/`、`\`、`..`、驱动器号或绝对路径。

### 清单

首版清单版本固定为 `1`：

```json
{
  "version": 1,
  "name": "示例分类模型",
  "model": {
    "file": "model.ms",
    "sha256": "64位小写十六进制摘要"
  },
  "input": {
    "kind": "image",
    "tensors": [
      {
        "name": "input",
        "dtype": "FLOAT32",
        "shape": [1, 224, 224, 3],
        "format": "NHWC"
      }
    ],
    "image": {
      "width": 224,
      "height": 224,
      "layout": "NHWC",
      "color": "RGB",
      "resize": "fit",
      "mean": [0.0, 0.0, 0.0],
      "std": [1.0, 1.0, 1.0]
    }
  },
  "output": {
    "kind": "classification",
    "tensor": {
      "name": "output",
      "dtype": "FLOAT32",
      "shape": [1, 1000]
    },
    "labels": {
      "file": "labels.txt",
      "sha256": "64位小写十六进制摘要"
    },
    "topK": 5
  }
}
```

`input.kind` 只允许 `image` 或 `text`。`output.kind` 只允许 `classification`、`text` 或 `raw`。

### 图片输入

清单必须声明：

- 宽、高
- `NHWC` 或 `NCHW`
- `RGB` 或 `BGR`
- `fit` 或 `fill`
- 每通道 `mean` 和 `std`
- 输入张量名称、类型、形状和格式

首版支持 `FLOAT32` 与 `UINT8` 图片张量。图片从相册或相机获得，按清单完成方向修正、缩放、通道排列和归一化。

### 文字输入

文字模型必须提供 `tokenizer.ttok`，并在 `input.text` 中声明：

- tokenizer 文件及 SHA-256
- 最大 token 数
- PAD、UNK、BOS、EOS ID
- 输入 ID 张量名称
- 可选 attention mask 张量名称

首版支持 `INT32` 的 `[1, sequenceLength]` 输入。Tokenizer 使用项目已有 TTOK 解析与编码规则，不从模型名称猜分词方式。

## 输入类型判断

应用完成两层校验后才决定页面输入控件：

1. 读取 `manifest.json` 的 `input.kind` 和张量契约。
2. 从 MindSpore Lite 模型读取所有输入张量的名称、类型、形状和格式。

图片清单必须匹配 rank-4 图片张量；文字清单必须匹配一个 input IDs 张量和可选 attention mask。清单与真实模型不一致时，模型包不可用，页面不显示可执行输入。

无法可靠识别时返回“不支持的输入契约”，不回退到猜测或随机数据。

## 输出解码

### 分类

- 校验输出张量名称、类型和形状。
- labels 行数必须与类别数一致。
- 展示 Top-K 标签和分数。

### 文字

- 输出可以是 `INT32` token IDs，或尺寸不超过 32 MiB 的 `FLOAT32` 序列 logits。
- token IDs 直接解码；logits 按每个位置取 argmax 后解码。
- 在 EOS 停止，忽略 PAD、BOS。
- 不做逐 token 自回归循环。

### 原始张量

- 展示张量名称、类型、形状、元素数量和有限数量的数值预览。
- 结果必须全部为有限值。
- 页面明确标注这是原始张量，不解释其业务语义。

## 页面

自定义模型页的顺序固定为：

1. 选择模型包
2. 模型信息
3. 动态输入区
4. 执行按钮与状态
5. 输出结果

包校验成功后展示模型名、输入类型、输入张量和输出类型。

- 图片模型显示相册和拍照。
- 文字模型显示文本框。
- 更换模型时清空旧输入和旧结果。
- 推理失败时保留当前模型和输入，显示具体错误并允许重试。
- 推理成功时显示执行耗时和解码后的端侧结果。

## 数据流

```text
选择 ZIP
  → 复制到私有缓存
  → 检查压缩与解压大小
  → 解压到新的临时目录
  → 解析清单并核对文件 SHA-256
  → 加载 model.ms 并读取真实张量
  → 清单与张量双重校验
  → 原子替换当前可用模型包
  → 根据 input.kind 显示输入控件
  → 预处理图片或文字
  → MindSpore Lite 单次前向
  → 按 output.kind 解码并展示
```

包校验失败时删除临时目录，不覆盖上一个可用包。

## 安全与资源限制

- 压缩包最大 256 MiB。
- `zlib.getOriginalSize()` 报告的解压大小最大 512 MiB。
- 文本 logits 最大读取 32 MiB。
- 解压目录位于应用私有缓存。
- 只读取清单允许的根目录文件。
- 拒绝绝对路径、父目录跳转、嵌套路径和符号链接。
- 模型及辅助文件必须通过 SHA-256。
- 输入和输出张量必须与清单完全匹配。
- 输出为空、非有限、尺寸超限或缺少辅助文件时失败。
- 模型加载与推理继续串行化，避免 MindSpore Lite 并发读写同一缓存文件。

## 测试

### 本地单元测试

- 场景检测和自定义模型入口默认可见。
- 清单版本、字段、路径、摘要和大小限制。
- 图片与文字输入类型判断。
- 清单和真实张量不一致时拒绝。
- 图片 NHWC/NCHW、RGB/BGR、归一化。
- TTOK 文本编码、input IDs 与 attention mask。
- 分类、文字和原始张量解码。
- 页面在模型切换、失败和重试时保留正确状态。

### 模拟器原生测试

准备两个微型真实 MindSpore Lite 模型包：

- 图片包：不同纯色图片产生可验证的不同输出。
- 文字包：不同短文本产生可验证的不同 token 或分类输出。

同时验证：

- 损坏 ZIP、错误摘要、缺少文件和张量不匹配均被拒绝。
- 失败包不会替换上一个可用包。
- 输出来自实际模型且随输入变化。

### 界面验收

使用 HDC 原生触点和截图检查：

- 高级区出现“场景检测”和“自定义模型”。
- 场景检测可进入并使用现有相册流程。
- 图片包显示图片输入。
- 文字包显示文本输入。
- 两种包都产生可解释的端侧结果。
- 页面滚动、长输出和底部导航无遮挡。
